# relay-node — 중계 노드 (Raspberry Pi 4)

담당: 김예훈, 이교민, 전승현

STM32 웨어러블의 센서 데이터를 BLE로 받아 MQTT 브로커로 중계한다.

```
STM32 ──UART(9600)──> HM-10 ──BLE──> RPi4 (relay_node) ──MQTT──> 브로커 ──> master_node
```

- HM-10 BLE 연결·자동 재연결, FFE1 notify 구독
- 7바이트 바이너리 패킷 재조립·체크섬 검증
- 네트워크 단절 대비 내부 큐 버퍼링 (재연결 시 자동 flush)
- 수신 시각 타임스탬프 부여 (패킷에 시각 필드 없음)

## 수신 패킷 (7바이트)

`firmware/App/Drivers/hm10.h` 와 동일 스펙.

| 오프셋 | 필드 | 범위 |
| --- | --- | --- |
| 0 | 헤더 `0xAA` | 고정 |
| 1 | `heart_rate` (bpm) | 0~255 |
| 2 | `spo2` (%) | 0~100 |
| 3 | `fall_flag` | 0 / 1 |
| 4~5 | `steps` (리틀엔디언 uint16) | 0~65535 |
| 6 | `checksum` | `[0]~[5]` 의 XOR |

기존 5바이트 규격에서 **체온을 빼고 걸음 수와 체크섬을 넣었다.** 체온은 측정
하드웨어가 없어 계속 0 더미만 실려 나갔고, 그 0 때문에 수신 측의 체온 기반
판정(서버 40도 알람, Qt 38도 위험)이 애초에 발동한 적이 없다.

예시: `AA 4E 62 01 E8 03 6C` = 78bpm, 98%, 낙상의심, 1000걸음

### 체크섬의 목적은 프레이밍이다

전송 오류 검출용이 아니다 — BLE 가 링크 계층에서 이미 CRC 와 재전송으로
무결성을 보장한다. 진짜 문제는 동기화다. 수신 측은 `0xAA` 를 찾아 패킷 시작을
잡는데 데이터 바이트에도 `0xAA`(170)가 나올 수 있어(걸음 수 170, 426, 682…)
가짜 헤더에 물릴 수 있다. 체크섬이 그것을 즉시 잡아 1바이트 밀고 재동기한다.

무작위 구간이 우연히 통과할 확률은 1/256 으로 CRC-8 과 같다 — 1바이트 검사의
한계다. 오정렬이 실제로 문제가 될 만큼 잦아지면 그때 폭을 늘린다.

필드 범위 검사는 남아 있지만 역할이 바뀌었다. 프레이밍은 체크섬이 책임지고,
범위 검사는 **송신 측 논리 오류**(범위 밖 값을 싣는 펌웨어 버그)를 잡는
보조 수단이다. 그래서 체크섬이 맞는데 범위를 벗어나면 조용히 버리지 않고
`stderr` 에 남긴다.

> ⚠ **펌웨어와 릴레이는 반드시 동시에 배포한다.** 길이가 어긋나면 프레이밍이
> 깨진다. 한쪽만 올리면 다음 패킷의 헤더까지 현재 패킷으로 삼키거나, 남는
> 바이트가 `0xAA`(170)일 때 가짜 헤더로 오인된다.

걸음 수는 `WearableData.steps` 로 MQTT 까지 그대로 발행된다. 같은 변경에서
`temperature` 필드는 스키마에서 제거했다 — 체온은 측정 하드웨어가 없어 구현된
적이 없다.

## 송신 패킷 (5바이트) — 시각 동기

BLE 는 양방향이라 같은 FFE1 특성에 write 하면 HM-10 이 웨어러블의 UART 로
흘려보낸다. 웨어러블에는 RTC 도 백업 배터리도 없어 부팅하면 **빌드 시각**으로
시작하므로, NTP 로 맞춰진 이쪽 시각을 내려보내 화면 시계와 자정 걸음수 리셋을
맞춘다.

| 오프셋 | 필드 | 범위 |
| --- | --- | --- |
| 0 | 헤더 `0x55` | 고정 (수신용 `0xAA` 와 구분) |
| 1 | 시 | 0~23 |
| 2 | 분 | 0~59 |
| 3 | 초 | 0~59 |
| 4 | `checksum` | `[0]~[3]` 의 XOR |

**연결 직후 1회 + 이후 10분마다** 보낸다(`TIME_SYNC_MS`). 주기 재전송은 웨어러블
SysTick 드리프트(하루 약 2초)를 함께 잡는 역할도 한다. 응답을 기다리지 않는
`write_command` 를 쓴다 — HM-10 투과모드는 확인 응답을 돌려주지 않는다.

---

펌웨어는 **1Hz 주기** 송신하고, 낙상 확정 시 주기를 기다리지 않고 즉시 1회 추가 송신한다.
`fall_flag` 는 엣지가 아니라 **레벨**이라 확정 후 5초간 1로 유지된다
(`HM10_FALL_HOLD_MS`). 그대로 흘리면 낙상 1건에 알람이 5~6번 뜨므로
게이트웨이가 **상승엣지(0→1)만** 낙상으로 발행한다.

## 발행 (MQTT)

토픽 `veda/wearable/data`, payload 는 `WearableData` JSON.

```json
{"device_id":"wearable_01","is_fall_detected":false,
 "heart_rate":78,"spo2":98,"steps":1000,"timestamp":1754000000000}
```

| 종류 | QoS |
| --- | --- |
| 바이탈 (`is_fall_detected: false`) | 0 — 빠르게, 유실 감수 |
| 낙상 (`is_fall_detected: true`) | 1 — 반드시 전달 |

## 빌드·실행

```bash
./install_deps.sh                      # 최초 1회
cmake -S . -B build && cmake --build build
./relay_node                           # 실행 파일은 relay-node/ 에 생긴다
```

실행 파일을 `build/` 가 아니라 `relay-node/` 에 두는 이유는 설정 파일을 실행
파일 옆에서 찾기 때문이다. `build/` 는 지웠다 다시 만드는 곳이라 거기에 설정을
둘 수 없다.

의존성은 `libmosquitto`, `nlohmann_json`, `SimpleBLE` 세 가지다. 앞의 둘은
apt 로 받고, SimpleBLE 는 apt 패키지가 없어서 `install_deps.sh` 가 소스에서
빌드해 `/usr/local` 에 설치한다. CMake 는 `find_package(simpleble)` 로 찾으므로
설치 후에는 소스 트리가 필요 없다.

## 설정

`relay-node.conf` 를 실행 파일과 같은 디렉터리에서 읽는다. `-c 경로` 로 다른
파일을 지정할 수 있다. 없으면 기본값으로 뜨고 그 사실을 출력한다.

```
broker_host  = localhost       # 배치할 때 서버 IP 로
broker_port  = 1883
device_id    = wearable_01     # WearableData.device_id
topic        = veda/wearable/data
hm10_addr    = 88:4a:ea:62:0b:03   # 모듈 교체 시 여기만 고친다
scan_ms      = 8000
reconnect_ms = 3000
debug_hex    = 0               # 1 이면 수신 원시 바이트를 hex 로 덤프
```

`debug_hex` 는 값이 이상할 때 파싱 전 단계를 확인하는 용도다. 예전 환경변수
`RELAY_DEBUG_HEX` 를 대체한다.

FFE0/FFE1 UUID 와 7바이트 패킷 규격은 설정으로 빼지 않았다. 기기가 바뀌어도
같은 값이고, 바뀐다면 코드도 같이 바뀌어야 하는 규격이기 때문이다.

## MQTT 클라이언트

`MqttClient_veda` 는 이 디렉토리에 사본을 두지 않고 프로젝트 공용 구현인
`MQTT/MQTT_prod/` 를 CMake 에서 직접 참조한다. 따라서 `relay-node/` 만 따로
떼어내면 빌드되지 않고, 저장소 전체가 있어야 한다.

`WearableData` 는 전 노드가 공유하는 구조체다. 필드를 바꾸면 master/alarm/qt
노드의 JSON 계약이 함께 바뀌므로 `MQTT/MQTT_dev/src/common/` 쪽도 같이 맞춰야 한다.

## 알려진 제약

- **체온은 지원하지 않는다** — 측정 하드웨어가 없어 구현된 적이 없다. 펌웨어
  패킷과 `WearableData` 양쪽에서 제거했다.
- **심박은 범위 검증을 하지 않는다** — 0~255 전체가 유효값이라 검사할 근거가
  없다. 걸음 수도 마찬가지다. 프레이밍은 체크섬이 맡으므로 문제되지 않는다.
