# 침상 이탈 — 위험도 판정 주체를 "침대"에서 "귀속된 입소자"로

> 상태: **제안** (미구현) · 작성 2026-08-21
> 대상: `server/modules/bed_egress_module.{hpp,cpp}`

---

## 1. 현재 동작과 문제

위험도의 원본은 사람 데이터(`residents.risk_level`)지만, 부팅 시점에 **침대 슬롯으로 복사**된 뒤로는 침대만 봅니다.

```cpp
// bed_egress_module.cpp — 부팅
patient_statuses_[ch][zone.roi_id] = level;      // 침대에 복사

// bed_egress_module.cpp — 판정
const PatientStatus status = statusOf(channel, zone_before);   // 발끝이 직전에 있던 침대
evt.resident_id = zones[zone_before].resident_id;              // 그 침대에 매핑된 사람
```

즉 **누가 나갔는지가 아니라 어느 침대에서 나갔는지**로 판정합니다. `IdentityTracker` 는 알람 경로에서 전혀 참조되지 않습니다.

### 재현되는 오작동

입소자 A(위험도 **하**)가 A침대에서 나와 B침대(위험도 **상**)를 스치고 방을 나가는 경우:

| 프레임 전이 | 판정 |
| --- | --- |
| A침대 → 바닥 | `statusOf(A침대)` = 하 → 무음 |
| 바닥 → B침대 | `zone_before == kNoZone` → 통과 |
| B침대 → 바닥 | `statusOf(B침대)` = 상 → 🔴 **경보** |

- 실제로 나간 사람은 **A**인데 이벤트에는 **B의 `resident_id`** 가 실립니다 → 로그·LED 호실·Qt·텔레그램이 전부 틀린 사람으로 나갑니다.
- 반대 방향(상 → 하 스침)이면 **진짜 이탈이 묻힙니다.** 실제 테스트에서 관측됨.
- 한 프레임만 밟아도 `last_zone_` 이 갱신되므로 "스치기"만으로 성립합니다.

**역설**: `IdentityTracker` 는 이 상황을 이미 알고 있습니다. 침대를 옮긴 트랙은 신뢰도가 `kConfBedSwap = 0.45` 로 강등되어 "미상"이 됩니다. 알람 모듈이 그 정보를 안 볼 뿐입니다.

### 함께 드러난 갭

알람 루프에는 **보호사 제외가 없습니다.** 재실 집계(`occupancy`)에만 `identify().caregiver` 체크가 있습니다. 보호사가 침대에 걸터앉았다 일어나면 이탈 경보가 납니다.

---

## 2. 목표

1. 위험도 판정과 이벤트의 `resident_id` 를 **그 트랙에 귀속된 입소자** 기준으로
2. 귀속이 불확실하면(미상) **안전한 쪽으로** 처리
3. 보호사는 알람 경로에서도 제외
4. **Qt·프로토콜·DB 무변경** — 서버 내부에서만 끝낸다

---

## 3. 변경 설계

### 3-1. 저장 키를 침대 → 입소자로

```cpp
// before
std::map<int, std::map<int, PatientStatus>> patient_statuses_;   // 채널 → 침대 → 등급
std::map<int, PatientStatus> channel_default_;

// after
std::map<int, PatientStatus> resident_statuses_;                 // 입소자 → 등급
std::map<int, PatientStatus> channel_default_;                   // 폴백용으로 유지
```

부수 효과로 **침대 매핑이 바뀌어도 위험도가 사람을 따라갑니다.** 지금은 `setRoiBindCallback` 에서 매번 다시 밀어넣어야 하는데(main.cpp:187) 그럴 필요가 없어집니다.

### 3-2. Qt 프로토콜은 그대로 두고 수신 시점에 변환

`setRiskLevelCallback(ch, roi_id, level)` 은 침대 기반입니다. **시그니처를 바꾸지 말고** 서버가 침대→입소자로 해석합니다.

```cpp
void BedEgressModule::updatePatientStatus(int channel, int roi_id, int status) {
    if (status < 1 || status > 3) return;
    const auto value = static_cast<PatientStatus>(status);

    if (roi_id == BedZoneStore::kRoiIdAll) {
        std::lock_guard<std::mutex> lock(mutex_);
        channel_default_[channel] = value;
        return;
    }
    // 침대 → 그 침대에 매핑된 입소자로 해석
    const auto zones = zones_ ? zones_->zones(channel) : std::map<int, BedZone>{};
    auto it = zones.find(roi_id);
    const int resident = (it != zones.end()) ? it->second.resident_id : 0;
    if (resident <= 0) return;              // 아직 사람이 안 붙은 침대 — 저장할 키가 없다

    std::lock_guard<std::mutex> lock(mutex_);
    resident_statuses_[resident] = value;
}
```

> ⚠️ `zones_->zones()` 는 자체 락을 가지므로 **`mutex_` 를 쥔 상태에서 부르면 안 됩니다.** 위처럼 락 밖에서 먼저 해석하세요.

`initializeFromDb` 도 침대 순회 대신 `residents` 를 직접 읽는 쪽이 자연스럽습니다(침대에 아직 안 붙은 입소자도 미리 로드됨).

### 3-3. 판정 주체 교체

```cpp
// ... zone_before == kNoZone / zone_now != kNoZone 처리까지는 그대로 ...

// [신규] 보호사는 이탈 대상이 아니다
const auto who = identity_ ? identity_->identify(channel, det.object_id) : IdentityTracker::Identity{};
if (who.caregiver) continue;

// [변경] 침대가 아니라 이 트랙에 귀속된 사람의 위험도로 판정
const int resident = who.named() ? who.resident_id : 0;
const PatientStatus status = statusOfResident(resident, channel);   // 미상 정책은 3-4

if (status == PatientStatus::LOW) continue;
if (status == PatientStatus::MEDIUM && !night) continue;

// ... 쿨다운 ...

EgressEvent evt;
evt.roi_id      = zone_before;   // 위치 정보는 그대로 — "어느 침대에서 나갔나"
evt.resident_id = resident;      // [변경] 신원은 귀속 기준 (0 = 미상)
```

`evt.roi_id` 와 `evt.resident_id` 가 서로 다른 침대를 가리킬 수 있습니다. 이건 버그가 아니라 **정보**입니다 — "3번 입소자가 1번 침대에서 나갔다" 는 오귀속 조사에 유용하므로 로그에 둘 다 찍으세요.

### 3-4. 미상(신뢰도 < 0.5) 정책 — **팀 결정 필요**

| 안 | 동작 | 장점 | 단점 |
| --- | --- | --- | --- |
| **① 미상 = 상** (권장) | 무조건 경보 | 놓침 0. `statusOf` 기본값 HIGH, 낙상 OR 판정과 **같은 철학** | 오경보 증가 |
| ② 침대 위험도로 폴백 | 현행 유지 | 변화 최소 | 1절의 오작동이 그대로 남음 |
| ③ `max(침대, 귀속)` | 둘 중 높은 등급 | 절충 | 규칙이 복잡해 설명하기 어려움 |

README에 이미 못박아둔 원칙 — *"둘 다 맞아야 알린다는 놓침을 구조적으로 만드는 설계"* — 과 일관되게 **①** 을 권합니다. 대신 이벤트 이름은 "미상"으로 나가므로 **틀린 이름으로 울리던 것이 정직한 미상으로 바뀝니다.**

```cpp
PatientStatus BedEgressModule::statusOfResident(int resident, int channel) const {
    if (resident > 0) {
        auto it = resident_statuses_.find(resident);
        if (it != resident_statuses_.end()) return it->second;
    }
    auto ch = channel_default_.find(channel);
    if (ch != channel_default_.end() && resident > 0) return ch->second;
    return PatientStatus::HIGH;      // 미상 · 미등록 → 안전 우선
}
```

### 3-5. (선택) 스침으로 라벨이 날아가지 않게

①을 택해도 **A(하)가 B를 스치고 나가면 여전히 울립니다** — 미상이 되니까요. 근본 해결은 `IdentityTracker` 쪽입니다.

```
현재: 다른 침대에서 1프레임이라도 잡히면 즉시 kConfBedSwap(0.45) 강등
개선: 새 침대에서 N프레임(또는 T초) 연속 체류해야 "이동"으로 인정
```

`Trace` 에 `pending_roi` + `pending_since` 를 추가하고, 임계 미만이면 기존 라벨을 유지하는 방식입니다. **낙상 판정(`main.cpp:286`)의 이름 정확도도 같이 올라갑니다.**

다만 이건 **`IdentityTracker` 튜닝값 변경**이라 낙상 시연에 회귀 위험이 있습니다. 3-1~3-4 와 **분리해서**, 발표 이후에 하는 것을 권합니다.

| # | 상황 | 기대 결과 |
| --- | --- | --- |
| 1 | 하 등급 입소자가 자기 침대에서 이탈 | 무음 |

| 5 | 중 등급, 주간 / 야간 | 주간 무음 · 야간 경보 |
| 6 | Qt에서 위험도를 하→상 변경 후 즉시 이탈 | 경보 (변환 경로 정상) |
