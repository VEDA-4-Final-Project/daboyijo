# 디자인 브리프 — 요양원 안전 관제 시스템 메인 관제 화면

이 문서는 **디자인 AI/디자이너에게 그대로 전달**하기 위한 브리프다.
아래 §7의 기술 제약을 반드시 읽고 시안을 만들어 달라 — 웹 기준으로 디자인하면 구현이 불가능하다.

---

## 1. 제품이 무엇인가

**요양원 안전 모니터링 시스템의 관제 데스크톱 앱.** 요양원 직원(간호사·요양보호사)이 상주하는 관제 PC에서 24시간 켜 놓고 쓴다.

**앱이 하는 일:** 요양실 4곳의 CCTV를 실시간으로 보여주고, AI가 낙상·침상이탈을 감지하고, 입소자가 착용한 웨어러블에서 산소포화도·심박을 받아 이상을 알린다. 사고가 나면 경보를 띄우고 현장 알림장치(LED·스피커)를 울린다.

**사용자의 실제 행동:** 대부분의 시간 동안 화면을 **보지 않는다.** 다른 일을 하다가 소리가 나거나, 지나가면서 흘깃 본다. 그래서 "지금 이상이 있는가?"가 **몇 미터 밖에서 0.5초 안에** 판별돼야 한다. 이게 이 화면의 존재 이유다.

**참고 톤:** 상용 VMS(영상관제 소프트웨어) — 한화비전 웹뷰어, Milestone XProtect, Genetec Security Center. **의료기기 모니터의 밀도 + 관제실 소프트웨어의 어두운 톤.** SaaS 대시보드(Linear/Notion/Vercel 계열)로 만들면 안 된다.

## 2. 화면 골격 (현재)

가로로 넓은 데스크톱 창. 기준 해상도 **1920×1080**, 최소 **1340×760**.

```
┌──────────────────────────────────────────────────────────────────┐
│  헤더 (높이 68px, 화면 폭 전체)                                    │
├────┬─────────────────────────────────────────────────────────────┤
│    │  경보 스트립 (폭 전체, 평시 얇음 / 경보 시 커짐)               │
│ 네 ├──────────────────────────────────┬──────────────────────────┤
│ 비 │                                  │                          │
│ 레 │   영상 그리드 2×2                 │   웨어러블 생체신호 레일   │
│ 일 │   (채널 1~4)                      │   (입소자별 타일 세로 목록) │
│    │                                  │                          │
└────┴──────────────────────────────────┴──────────────────────────┘
```

**비중:** 영상 그리드가 가로의 최소 70%. 우측 레일은 232~268px 고정.

## 3. 각 영역 상세

### 3.1 헤더 (좌→우)

| 요소 | 내용 | 비고 |
|---|---|---|
| 로고 | "다보이조" 텍스트 | 좌측 끝 |
| *(빈 공간)* | | |
| 방송 버튼 | 마이크 아이콘 + "방송" | **누르고 있는 동안만** 현장에 음성 송출. 누르는 중엔 빨갛게 |
| 연결 상태 배지 | 점 + "영상 서버 연결됨" | **현재 숨김 상태.** 다시 보이게 할지는 디자인 판단 |
| 시계 | `2026-08-15 22:38:49` | 초 단위로 매초 갱신 |
| 도움말 | ⓘ 아이콘 + "도움말" | |
| 테마 토글 | 해/달 아이콘 | 다크↔라이트 |
| 사용자 칩 | 이니셜 + 이름 + "로그아웃" | |

### 3.2 좌측 네비 레일

세로 메뉴 5개, 접기/펼치기 가능(펼침=아이콘+글자, 접힘=아이콘만):

**실시간 관제** / 이벤트 기록 / 일일 리포트 / 입소자 관리 / 장치 설정

### 3.3 경보 스트립 (이 화면에서 가장 중요)

**항상 보인다.** 조작 없이도 활성 경보를 알 수 있어야 한다.

| 상태 | 표시 |
|---|---|
| 경보 0건 | 얇은 줄. `✓ 활성 경보 없음 · 모든 침대 정상 범위` |
| 경보 1건 | 커지고 심각도 색으로 반전. `✖ 낙상 · 3번 침대` |
| 경보 여러 건 | 심각도 높은 순 최대 3줄, 넘치면 `+N건 더` |

**심각도 5단계(ISA-18.2 표준):**

| 등급 | 색 | 도형 | 쓰이는 경우 |
|---|---|---|---|
| critical | 빨강 | ✖ | 낙상 |
| high | 주황 | ▲ | 침상이탈 |
| medium | 노랑 | ◆ | 생체신호 주의 |
| info | 파랑 | ● | 정보 |
| normal | 초록 | ✓ | 정상 |

⚠️ **도형은 장식이 아니라 필수다.** 접근성 기준(WCAG AA)을 맞추려고 5색을 조정했더니 그레이스케일 명도 폭이 0.0353(임계 0.04 미만)으로 수렴했다 — **색맹 사용자에겐 다섯 등급이 거의 같은 회색으로 보인다.** 그래서 색과 도형을 반드시 함께 쓴다. 시안에서 도형을 빼지 말 것.

### 3.4 영상 그리드

- **2×2 균등 배치**가 기본. 채널 1~4.
- **스포트라이트 모드**: 낙상이 감지된 채널이 좌측 대형(약 75%)으로 커지고 나머지 3개가 우측에 작게 세로로 붙는다.
- 각 영상 위 오버레이:
  - **좌하단**: `CH1` 태그(강조색) + 병상·이름(선택)
  - **우상단**: 빨간 점 + `LIVE` / 회색 점 + `미연결`
  - 낙상 시 카드 테두리가 빨갛게 **0.45초 간격 점멸**
- 침대 영역(ROI)을 영상 위에 다각형으로 겹쳐 그리고, **클릭하면 그 침대가 선택된다** (침대마다 색이 다름, 최대 8개)

### 3.5 우측 생체신호 레일

섹션 제목 "웨어러블 생체신호" + 입소자별 타일 세로 목록(스크롤).

**타일 1개 구성:**
```
│ 전승현      채널 1              ✓ 정상
│ ◇ SpO₂  98 %    ∿ HR  72 bpm
│ ▁▂▃▅▃▂▁▂▃▅▇▅▃▂
↑ 좌측 3px 세로 등급 레일
```
- 이름(개인정보) / 채널 / 상태 배지(도형+글자)
- SpO₂(%)와 심박(bpm) — **모노스페이스 숫자**
- 심박 추세 미니 그래프 (34px 높이)
- 신호 없을 때: 숫자는 `--`, 배지는 `○ 대기`, 그래프는 옅은 기준선 하나
- 타일 개수는 입소자 수만큼 가변(0~8)

## 4. 반드시 지켜야 할 기능 요구

1. **원거리 판별** — 2~3m 밖에서 0.5초 안에 "이상 있음/없음"이 판별될 것. 경보 상태만 원거리에서 눈에 띄고, 나머지는 안 띄어도 된다.
2. **비식별화** — **입소자 이름·방 번호는 가까이 가야 읽히는 크기에 머물러야 한다.** 관제실 밖 복도에서 이름이 읽히면 개인정보보호 위반이다. 원거리 강조는 오직 경보 상태에만.
3. **색 단독 금지** — 모든 상태는 색 + (도형/크기/위치) 중 최소 하나로 이중 표시.
4. **영상이 주역** — 영상 그리드가 화면에서 가장 큰 시각적 비중.

## 7. 기술 제약 — 시안 만들기 전에 반드시 읽을 것

**구현 환경은 웹이 아니라 C++ **Qt 6 Widgets**이고, 스타일은 **QSS**(CSS의 아주 제한된 부분집합)로 적용한다.** 웹 기준으로 디자인하면 상당 부분을 구현할 수 없다.

### 쓸 수 없는 것 (QSS 미지원)

| 안 되는 것 | 비고 |
|---|---|
| `box-shadow` | 그림자는 위젯마다 코드로 따로 붙여야 해서 비용이 큼. **시안에서 그림자에 의존하지 말 것** |
| `transform` (회전·기울임·스케일) | 전혀 없음 |
| `transition` / `animation` / 키프레임 | CSS로는 불가. 애니메이션은 C++ 코드로 하나씩 구현해야 함 |
| `backdrop-filter`, 블러, 글래스모피즘 | 불가 |
| `flexbox` / `grid` | 레이아웃은 QSS가 아니라 C++ 레이아웃 코드가 담당 |
| CSS 변수(`var()`) | 없음. 토큰은 빌드 시 문자열 치환 |
| SVG를 CSS로 삽입 | 불가. 아이콘은 코드로 그리거나 이미지 파일로 동봉 |
| `opacity` (위젯 전체) | QSS로는 안 되고 색의 alpha로만 |
| 커스텀 폰트 | 동봉하지 않는 한 시스템 폰트만. **한글이 반드시 필요** |
| 가변 코너 반경(코너별 다른 값) | 위젯에 따라 불안정 |

### 쓸 수 있는 것

- `background`, `color`, `border`, `border-radius`(전체 동일 값), `padding`, `margin`
- `qlineargradient` (선형 그라데이션은 됨)
- `font-size`, `font-weight`, `font-family`, `letter-spacing`
- 상태 선택자: `:hover`, `:checked`, `:disabled`
- **속성 선택자**: `#alertBanner[severity="critical"]` 같은 형태 — 상태별 스타일링의 주력 수단
- 복잡한 그래픽(아이콘·그래프·ROI 오버레이)은 **`QPainter`로 직접 그린다** — 즉 도형·선 기반이면 무엇이든 가능하지만, 각각 코드를 짜야 하므로 개수를 절제해 달라

### 실무적 요청

- **간격·크기를 구체적 px로** 지정해 달라(4의 배수 권장). "여유있게" 같은 서술은 구현 단계에서 다시 추측해야 한다.
- **각 상태(정상/주의/위험/신호없음)의 시안을 따로** 그려 달라. 특히 경보 0건일 때와 3건일 때의 경보 스트립.
- 폰트는 시스템 폰트 전제(Windows: Segoe UI / 맑은 고딕, macOS: SF Pro / Apple SD Gothic Neo). 특정 유료 폰트를 전제로 하지 말아 달라.

## 8. 한 줄 요약

> **24시간 켜두는 요양원 관제 화면. 어두운 상용 VMS 톤. 영상 4분할이 주역이고, 경보는 몇 미터 밖에서 0.5초 만에 보여야 하지만 입소자 이름은 가까이 가야 읽혀야 한다. 색만으로 상태를 구분하면 안 되고 도형을 반드시 함께 쓴다. 구현은 Qt QSS라 그림자·애니메이션·블러는 쓸 수 없다.**
