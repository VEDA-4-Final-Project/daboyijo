# 웨어러블 펌웨어 아키텍처 전환: 타이머 폴링 → 센서 인터럽트 + FIFO 블록

STM32F411 / MAX30102 (PPG) / BMI270 (IMU)

---

## 1. 왜 바꿨나

기존 방식은 **MCU가 시계를 보고 센서에게 물어보는** 구조였다. 20ms마다 타이머가
깨우고, 그때마다 센서에서 샘플 하나를 꺼내온다.

여기엔 세 가지 문제가 있었다.

1. **전력** — 센서에 새 데이터가 있든 없든 초당 50번 깨어난다. 메인 루프는 아예 잠들지 않았다.
2. **정확도** — 샘플이 하나씩 도착하므로 알고리즘이 앞뒤 문맥을 볼 수 없다.
   이동평균은 인과(causal) 필터일 수밖에 없고, 피크 검출은 지나간 점만으로 판단해야 한다.
3. **타이밍 결합** — 타이머 주기와 센서 ODR이 따로 놀면 조용히 어긋난다.
   실제로 PPG가 25Hz로 나오는데 알고리즘은 50Hz로 계산해 **심박수가 정확히 2배**로 나오고 있었다.

전환 후에는 **센서가 준비됐다고 알려줄 때만** MCU가 깨어나고, 한 번에 한 뭉치씩 가져온다.

---

## 2. 한눈에 보는 비교

| 항목 | 타이머 폴링 (기존) | 센서 인터럽트 + FIFO 블록 (현재) |
|---|---|---|
| 트리거 | TIM3 50Hz 타이머 | 센서 FIFO 인터럽트 (EXTI) |
| PPG 수거 단위 | 6바이트 (1샘플) | **150바이트 (25샘플 = 0.5초)** |
| IMU 수거 단위 | 14바이트 (1샘플) | **최대 480바이트 (80프레임)** |
| PPG 실효 레이트 | 25Hz (알고리즘은 50Hz 가정 → **버그**) | 50Hz (드라이버 헤더에서 단일 정의) |
| IMU ODR | ACC 50Hz / GYR 100Hz (불일치) | 100Hz 통일 |
| 가속도 범위 | ±2g (**충격 측정 불가**) | ±16g |
| 유휴 상태 | 공회전 (sleep 없음) | `WFI` sleep (Stop 모드는 빌드 플래그) |
| 필터 | 인과 6탭 이동평균 | **영위상 중심 7탭** (위상 지연 0) |
| 피크 검출 | 3점 비교 | 5점 비교 + 창 통계 적응형 문턱 |
| 낙상 판정 | 무중력 → 충격 **전방 대기** | 충격 → 과거 **백트래킹** |

## 3. 동작 방식

### 3.1 기존: 타이머 폴링

```
TIM3 (20ms)
   └─> SPI DMA 14B 요청 ──> BMI270 레지스터 직접 판독
                              └─> 콜백 ──> 샘플 1개 처리

MAX30102 PPG_RDY 인터럽트 (샘플마다)
   └─> I2C DMA 6B ──> 콜백 ──> 샘플 1개 처리
```

- MCU는 항상 깨어 있고 메인 루프가 계속 돈다.
- 센서 FIFO는 사실상 쓰이지 않는다.

### 3.2 현재: 인터럽트 + FIFO 블록

```
MAX30102 내부 FIFO에 25샘플 적재 (0.5초)
   └─> A_FULL 인터럽트 (PB0 하강엣지)
        └─> I2C DMA 150B 일괄 수거
             └─> 25개 배열 단위 신호처리

BMI270 내부 FIFO에 워터마크 도달
   └─> INT1 (PA5 상승엣지)  ※ 미배선 시 700ms 폴링 폴백
        └─> FIFO 길이 조회 ──> SPI DMA 블록 수거
             └─> 프레임 배열 단위 낙상 판정

처리할 블록이 없으면 → __WFI() 로 취침
```

핵심은 **인터럽트가 "데이터 한 뭉치가 준비됐다"는 신호**라는 점이다.
MCU는 그 사이 아무것도 하지 않는다.

## 4. 정량 비교

| 지표 | 기존 | 현재 | 변화 |
|---|---|---|---|
| BMI270 SPI 트랜잭션 | 50회/초 | 약 1.4회/초 | **-97%** |
| MAX30102 I2C 트랜잭션 | 25회/초 | 2회/초 | **-92%** |
| 트랜잭션당 데이터 | 6~14 B | 150~480 B | 오버헤드 분산 |
| 메인 루프 | 공회전 | WFI 취침 | — |

> **전력에 대한 정직한 단서**
> 현재 `LOWPOWER_STOP_MODE 0` 상태에서는 SysTick이 1ms마다 코어를 깨우므로,
> 지금의 이득은 **구조적**인 것이다(버스 트랜잭션 97% 감소, 루프 공회전 제거).
> 큰 폭의 전류 감소는 Stop 모드로 전환할 때 나온다. 다만 Stop 모드에서는
> `HAL_GetTick()`이 멈추므로 BLE 주기 송신을 RTC 웨이크업 타이머로 옮겨야 한다.

## 5. 알고리즘에 생긴 실질적 차이

블록 단위 수거의 진짜 가치는 전력이 아니라 **"앞뒤를 볼 수 있다"** 는 데 있다.

### 5.1 낙상 판정: 전방 대기 → 백트래킹

**기존 (전방 대기)**
```
무중력 감지 → 타임아웃 카운터 시작 → 그 안에 충격이 오는가?
```
자유낙하 구간이 짧거나 샘플 사이에 끼면 **영구히 놓친다.**

**현재 (백트래킹)**
```
충격 감지 (놓치기 어려운 큰 신호) → 링버퍼를 거꾸로 훑어 자유낙하가 선행했는지 확인
```
- 128샘플 링버퍼가 **블록 경계를 넘어** 유지되므로, 낙상이 두 블록에 걸쳐도 정상 판정된다.
- 트리거를 "크고 확실한 신호"로 잡으니 검출 신뢰도가 올라간다.

### 5.2 PPG: 영위상 필터

인과 필터는 반드시 위상 지연이 생기고, 그만큼 피크 위치가 밀린다.
블록에는 뒤쪽 샘플이 이미 들어와 있으므로 **중심 대칭 FIR**을 쓸 수 있다.
지연이 0이라 RR 간격 정확도에 직접 도움이 된다.

### 5.3 창 통계 기반 적응형 문턱

2초 창의 평균·표준편차로 피크 문턱을 만든다. 고정 임계값은 착용 부위·혈류·
LED 전류에 따라 수십 배 달라지는 PPG 진폭에 대응할 수 없다.

## 6. 전환 과정에서 드러난 버그들

아키텍처를 바꾸는 것보다 **기존에 숨어 있던 결함을 찾는 데** 시간이 더 들었다.

### 센서 설정
| 문제 | 영향 |
|---|---|
| PPG 25Hz인데 알고리즘은 50Hz 가정 | **심박수가 정확히 2배** |
| 가속도 범위 ±2g | 낙상 충격(3~6g)이 축마다 포화 → 측정 자체가 불가 |
| PC13 LED: GPIOC 클럭 미설정 | 부팅 실패 표시가 조용히 무동작 |
| BMI270 init에 소프트 리셋 없음 | 재시도 3회가 전부 동일하게 실패 |
| 8KB 컨피그를 6MHz로 업로드 | 점퍼선에서 스트림 손상 → `init_err` |
| `INIT_CTRL` 후 고정 30ms 대기 | 근거 없는 값. 폴링으로 교체 |
| 피처 페이지를 바이트 단위로 기록 | 하위 바이트가 0으로 날아감 → 버스트 기록 필요 |

### 동시성 / 통신
| 문제 | 영향 |
|---|---|
| DMA 전송 중 MCU 리셋 | I2C 슬레이브가 SDA를 붙들어 **전원 재인가 전까지 복구 불가** |
| ISR 안에서 `HAL_Delay()` 호출 | SysTick(우선순위 15)이 선점 못 해 **시스템 영구 정지** |
| 블로킹 I2C와 EXTI DMA가 같은 핸들 공유 | 상태 머신 파손 |
| AGC가 "맥박 확인" 플래그를 참조 | **순환 의존** — AGC↔맥박이 서로를 기다려 둘 다 멈춤 |

> 뒤의 네 가지는 모두 **블록 전송으로 바뀌면서 노출된** 문제다.
> 6바이트 전송일 때는 리셋이 전송 구간에 걸릴 확률이 낮았지만,
> 150바이트를 0.5초마다 돌리면 확률이 크게 올라간다.

## 8. 남은 한계

- **손목 PPG 신뢰도** — MAX30102는 적색·적외선만 있어 손목에 구조적으로 불리하다.
  손목시계형 기기가 녹색 LED를 쓰는 이유. 근본 해결은 MAX30101/MAX86140 계열로 교체.
- **Stop 모드 미적용** — 빌드 플래그로 분리되어 있다. 전환 시 RTC 웨이크업 타이머 필요.

## 9. 결론

| | 타이머 폴링 | 인터럽트 + FIFO 블록 |
|---|---|---|
| 설계 사상 | MCU가 시계를 보고 **물어본다** | 센서가 준비되면 **알려준다** |
| 데이터 단위 | 샘플 | 배열(블록) |
| 알고리즘 시야 | 지나간 점만 | **앞뒤 문맥** |
| 확장성 | 센서 추가 시 타이밍 재조정 | 각 센서가 독립적으로 자기 페이스로 동작 |

타이머 방식은 구현이 단순하지만, **정확도와 전력을 동시에 희생**한다.
인터럽트 + FIFO 블록 방식은 초기 구현 비용이 크고 동시성 버그가 드러나기
쉽지만, 한번 자리 잡으면 두 축을 모두 개선한다.

특히 낙상 감지처럼 **사건 전후 맥락이 판정의 본질인 알고리즘**에서는
블록 단위 처리가 선택이 아니라 전제 조건에 가깝다.
