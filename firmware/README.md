# firmware — STM32 웨어러블 펌웨어

담당: 김예훈, 이교민, 전승현

손목에 착용해 **낙상 · 심박 · SpO2 · 걸음 수**를 수집하고, BLE로 중계 노드에 1초마다
보냅니다. 낙상은 기기에서 직접 확정합니다 — 서버 판정을 기다리지 않습니다.

## 하드웨어

| 부품 | 인터페이스 | 역할 |
| --- | --- | --- |
| STM32F411CEU6 (BlackPill) | — | 메인 MCU |
| **BMI270** (IMU) | **SPI2** (CS PA4) + INT1(PA5) · FIFO를 DMA로 수거 | 낙상 감지, 만보기, 손목 들기 |
| **MAX30102** (PPG) | **I2C1** + INT(PB0) · FIFO를 DMA로 수거 | 심박, SpO2, 착용(광학 접촉) 판정 |
| **HM-10** (BLE) | USART2 (투과모드) | 중계 노드와 **양방향** 패킷 송수신 |
| **ST7789** (LCD) | SPI1 + DC(PA8) / CS(PB4) / RST(PA1) / BL(PB1) | 240×280 손목 화면 (LVGL 9.1) |
| 배터리 분압 | ADC1_IN7(PA7), VREFINT 동시 측정 | 잔량 표시 |

> 체온 센서는 **없습니다.** 초기 설계에 있었으나 측정 하드웨어를 구하지 못해
> 펌웨어·패킷·서버 스키마 전 구간에서 제거했습니다.

## 알고리즘 (`App/Algorithms/`)

### 낙상 감지 — 3단계 백트래킹 (`fall_detection.c`)

```
2단계  충격       SVM > 10g                    ← 트리거(먼저 잡는다)
1단계  자유낙하   SVM < 0.75g 가 3샘플 이상 연속  ← 충격 시점에서 1.2초 링버퍼를 되짚는다
3단계  정지       충격 후 3초 관찰(앞 0.5초는 잔여 진동 무시),
                  |SVM-1g| > 0.25g 인 샘플이 1.5초 미만
         ↓
   세 조건 + '광학 접촉' 상태여야 신고
```

> 판정은 **충격을 먼저 포착하고 과거를 되짚는 백트래킹**입니다. 자유낙하를 먼저 보고
> 충격을 기다리는 전방 판정은 자유낙하 구간이 짧으면 통째로 놓칩니다.

- **자유낙하 임계가 이론값(0.5g)이 아니라 0.75g인 이유**: 사람이 넘어질 때는 팔이
  휘둘리고 몸이 가구·팔다리에 부딪히며 감속돼, 손목 최저값이 0.6~0.8g에 머물고
  이론적 자유낙하까지 내려가지 않습니다.
- ⚠️ **가속도 범위는 ±16g여야 합니다.**(`BMI270_ACC_RANGE_16G`, ODR 100Hz) ±2g로는
  낙상 충격이 축마다 포화돼 임계값 비교 자체가 성립하지 않습니다.
- 움직임 지표는 블록 내 SVM의 **표준편차**입니다(평균 편차가 아님). 가속도계 스케일
  오차로 정지 상태에서도 SVM이 1.04로 읽히는데, 평균 편차를 쓰면 그 오차가 가짜
  바닥값으로 깔려 정지와 움직임을 구분하지 못합니다. 표준편차는 상수 오차에 0이 됩니다.
  → 정지 0.001~0.003 / 움직임 0.1 이상

### 심박 · SpO2 (`heart_rate_calc.c`)

- MAX30102 IR/RED 채널(50Hz, FIFO 25샘플=0.5초 블록) → AGC(LED 전류 자동 조절)
  → 7-tap 이동평균 LPF → **피크 검출 + 자기상관(autocorrelation) 이중 추정** 교차 확인
- **모션 블랭킹** — 움직이는 구간은 PPG를 신뢰하지 않습니다
  (`MOTION_BLANKING_THRESHOLD_G` 0.05, SpO2는 더 엄격한 `SPO2_MOTION_LIMIT_G` 0.008)
- **착용 판정** — 낙상 게이트는 **광학 접촉**(`HeartRateCalc_HasContact`, IR DC·반사율 기반)을
  씁니다. 원래는 맥박까지 확인하는 `HeartRateCalc_IsWorn()` 이었으나, 이 센서로는 손목에서
  맥박이 잡히는 일이 드물어 사람이 차고 있는데도 게이트가 열리지 않아 낙상이 묻혔습니다.
  ⚠️ 대가로 책상·바닥에 엎어둔 상태에서도 접촉이 참이 될 수 있습니다(맥박이 30초간 없으면
  접촉 판정이 해제되므로 창은 그만큼으로 제한). `IsWorn()` 은 현재 어떤 게이트에도 쓰이지 않습니다
- 인터럽트 유실 시 폴링으로 자동 복구, I2C 행 걸림 복구 로직 포함

### 만보기 (`step_counter.c`)

- BMI270 FIFO 블록 단위 걸음 검출 + 시간 게이트(30~200spm) + 리듬 게이트(직전 간격
  ±50% 안으로 4연속이어야 인정, 보류분은 한꺼번에 가산)
- **착용 여부를 묻지 않고 상시 계수**합니다 — 손에 들고 있어도 셉니다
- 자정에 자동 초기화 (`App/Services/app_clock.c`)

### 손목 들기 (`wrist_raise.c`)

- 중력 벡터만 남긴 뒤 화면 법선축 성분(`facing`) 하나로 자세를 봅니다. 자이로는 쓰지 않습니다
- **자세와 점등을 분리**합니다 — 자세(`IsRaised`)는 히스테리시스(켜짐 60° / 꺼짐 70°)로
  판정해 **끌 때** 쓰고, 점등 이벤트(`ConsumeRaiseEvent`)는 '움직인 뒤 화면이 위를 본 채
  멈춘 순간'에만 나서 **켤 때** 씁니다
- 상승 엣지 하나로 켜면 타임아웃 직후 팔이 아직 올라가 있다는 이유로 다시 켜지고, 반대로
  팔을 든 채 버티면 새 엣지가 영영 오지 않습니다. '무장(armed)' 상태를 두어 둘 다 막습니다
- ⚠️ `WRIST_RAISE_AXIS`는 조립 방향에 따라 **실측으로 맞춰야** 합니다

## 화면 · 배터리 (`App/Services/`)

ST7789 240×280 패널에 **LVGL 9.1** + SquareLine Studio 생성 UI(`UI/`)를 올립니다.

- **손목을 들었을 때만 켜집니다** (`display_service.c`). 꺼져 있는 동안은 백라이트뿐 아니라
  패널을 SLPIN 으로 재우고 `lv_timer_handler()` 자체를 호출하지 않습니다
- 최대 점등 60초(`DISPLAY_ON_MS`), 켠 직후 0.5초는 소등 판정을 하지 않습니다
- 켜는 순서: SLPOUT → 라벨 갱신 → 즉시 렌더 → **그 다음** 백라이트. 백라이트를 먼저 켜면
  이전 프레임(몇 분 전 시각)이 잠깐 보입니다
- 표시 항목: 시각(BLE 시각 동기), 심박, 걸음 수, 배터리 잔량
- **배터리** (`battery.c`) — 분압 → ADC1_IN7, 내부 기준 `VREFINT`를 같이 재서 VDD 변동을
  상쇄합니다. 1초 주기 8회 오버샘플, LPF + 2%p 히스테리시스.
  스위치 OFF(USB 전용 급전) 상태에서는 분압기가 끊겨 `Battery_IsValid()`가 0이고 화면에 `--`

> ⚠️ 현재 **화면 심박은 더미값(60~65)** 입니다 (`DISPLAY_DUMMY_HR 1`). 센서 한계로 손목에서
> 맥박이 잘 잡히지 않아 시연용으로 넣은 임시 조치이며, **BLE로 나가는 값은 실측**입니다.

## 통신 — BLE 7바이트 패킷

**규격 원본은 [`App/Drivers/hm10.h`](App/Drivers/hm10.h)입니다.**
(`../protocol/protocol.h`는 채택되지 않은 초기 설계입니다 — 참고하지 마세요.)

| 오프셋 | 필드 | 범위 |
| --- | --- | --- |
| 0 | 헤더 `0xAA` | 고정 |
| 1 | `heart_rate` (bpm) | 0~255 |
| 2 | `spo2` (%) | 0~100 |
| 3 | `fall_flag` | 0 / 1 |
| 4~5 | `steps` (리틀엔디언 uint16) | 0~65535 |
| 6 | `checksum` | `[0]~[5]`의 XOR |

예시: `AA 4E 62 01 E8 03 6C` = 78bpm, 98%, 낙상의심, 1000걸음

- **1Hz 주기** 송신. 낙상 확정 시 주기를 기다리지 않고 즉시 1회 추가 송신
- `fall_flag`는 엣지가 아니라 **레벨** — 확정 후 5초간 1로 유지됩니다(`HM10_FALL_HOLD_MS`).
  중계 노드가 **상승엣지(0→1)만** 낙상으로 발행합니다
- **체크섬의 목적은 오류 검출이 아니라 프레이밍**입니다. BLE가 링크 계층에서 이미 CRC와
  재전송으로 무결성을 보장합니다. 진짜 문제는 데이터 바이트에도 `0xAA`(170)가 나올 수
  있다는 것(걸음 수 170, 426, 682…)이고, 체크섬이 가짜 헤더를 즉시 잡아 재동기시킵니다

> ⚠️ **중계 노드와 반드시 동시에 배포하세요.** `relay-node/src/main_relay.cpp`의
> `PKT_LEN`이 이 길이와 같아야 합니다. 한쪽만 올리면 프레이밍이 통째로 어긋납니다.

### 시각 동기 — 양방향 (`0x55` / `0xA5`)

웨어러블에는 RTC도 백업 배터리도 없어 부팅하면 **빌드 시각**으로 시작합니다.
중계 노드가 NTP로 맞춘 시각을 내려보내 화면 시계와 자정 걸음수 리셋을 맞춥니다.

**수신 (중계 노드 → 웨어러블, 5바이트)**

| 오프셋 | 필드 | 범위 |
| --- | --- | --- |
| 0 | 헤더 `0x55` | 고정 (송신용 `0xAA`와 구분) |
| 1~3 | `hour` / `minute` / `second` | 0~23 / 0~59 / 0~59 |
| 4 | `checksum` | `[0]~[3]`의 XOR |

**시각 요청 (웨어러블 → 중계 노드, 3바이트)** — 헤더 `0xA5`, 종류 `0x01`(시각), XOR 체크섬.
중계 노드의 10분 주기만 기다리면 그동안 틀린 시각이 화면에 남습니다. 특히 **MCU만 리셋되고
BLE 링크는 살아있는 경우** 중계 노드 입장에선 아무 일도 없었으므로, 웨어러블이 먼저 묻습니다.
동기가 설 때까지 5초 간격으로 재시도하고, 맞춰지면 스스로 멈춥니다.

수신 경로 진단은 `hm10_get_rx_stats()`로 봅니다 — `RX=0`이면 HM-10 TX → PA3 배선이 죽은
것이고, `RX`는 느는데 `bad`만 늘면 양쪽 규격 불일치입니다.

## 운영 · 디버깅

| 항목 | 방식 |
| --- | --- |
| **로그** | `printf` → **USB CDC** (`_write` 재정의). USB 미연결 시 자동 무시 |
| **업로드** | ST-LINK 없이 **USB DFU 모드** |
| **부팅 실패 알림** | 센서 초기화 3회 재시도 후에도 실패하면 **LED 깜빡임 횟수**로 표시 (USB 미연결 시 유일한 단서) |
| **센서 장애 격리** | BMI270 실패 → 낙상·만보기만 중단 / MAX30102 실패 → 심박·SpO2만 중단. 나머지는 계속 동작 |
| **INT 폴백** | BMI270 INT1이 안 오면 폴링 모드로 자동 전환 후 경고 출력 |
| **저전력** | WFI Sleep(기본, USB 로그 유지) ↔ Stop Mode(`LOWPOWER_STOP_MODE`, USB 끊김). Stop 진입 시 HSE/PLL을 깨어난 직후 복구 |
| **워치독** | IWDG 약 8초. 메인 루프가 한 바퀴 돌 때만 갱신합니다 — 어느 단계든 멎으면 리셋. '측정은 멈췄는데 BLE로 0만 계속 보내는' 상태가 가장 위험하기 때문입니다 |
| **I2C 락업 복구** | 부팅 시 `I2C1_BusRecovery()`로 SCL을 직접 흔들어 슬레이브를 빼냅니다. DMA 중 MCU가 리셋되면 슬레이브가 SDA를 붙든 채 남아 "전원 인가 후 첫 부팅만 성공"이 됩니다 |

개발 환경: **STM32CubeIDE v1.18.1**, STM32CubeMX v6.14.1, ARM GCC

## 알려진 제약

- **체온 미지원** — 측정 하드웨어가 없어 구현된 적이 없습니다.
- **자이로 미사용** — BMI270의 자이로는 전원을 켜지 않습니다(절전). PPG 모션 블랭킹은
  가속도 기반 `FallDetection_GetBlockMotion()`을 대신 씁니다.
- **SVM은 순수 회전에 눈이 멉니다** — 손목을 천천히 돌리면 축별 값은 크게 변해도 벡터
  크기는 계속 1g라 움직임 지표가 거의 0으로 나옵니다. 낙상 판정에는 무해하지만, PPG
  입장에선 광 경로가 실제로 틀어지는 상황을 '정지'로 통과시킵니다.
  **SpO2가 이유 없이 튀면 여기를 의심하세요.**
- **화면 심박이 더미값입니다** — `display_service.c`의 `DISPLAY_DUMMY_HR`을 0으로 되돌리면
  실측값이 뜨지만, 손목에서 맥박이 잘 잡히지 않아 대부분 `--`로 남습니다.
- **SOS 노크 인식은 구현되지 않았습니다** (초기 기획 항목).
